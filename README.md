## 1. 当前状态判断

### 1.1 已完成的主链路

- [x] 首页已切为成长 / 挑战导向，不再只是游戏列表
- [x] 本地玩家档案、章节进度、任务状态、奖励领取、升级推进已具备基本闭环
- [x] WebView 游戏结果可以回流任务系统
- [x] 已消费历练配置相关接口：`version / config / home / chapter / reward-packages / fallback`
- [x] 已建立 `远端配置 -> Room(app_config) -> assets fallback` 读取链路
- [x] 首启协议确认、设置页隐私政策、用户协议、广告隐私选项已落地
- [x] 已具备基础埋点与基础崩溃记录能力，支持按配置启用 Sentry
- [x] 已验证 `./gradlew :app:assembleDebug` 与 `./gradlew :app:testDebugUnitTest` 通过

### 1.2 当前仍然阻塞上线的核心问题

- [ ] release 仍未切到正式线上环境，默认仍带局域网 beta 联调地址
- [ ] 广告仍默认测试广告位，正式广告配置未落地
- [ ] release 签名、AAB、版本号、混淆后回归尚未形成完整发布流程
- [ ] `fallbackToDestructiveMigration()` 仍在使用，正式升级存在本地数据丢失风险
- [ ] 法务页面和商店材料仍有占位信息，真实邮箱和主体信息未替换
- [ ] Data Safety、广告声明、年龄分级等商店合规仍未最终提交
- [ ] 自动化测试覆盖仍不足，关键链路主要依赖人工回归
- [ ] Manifest 中仍存在疑似无用定位权限，需在上线前确认并清理

### 1.3 本次版本明确不做

- [x] 排行榜
- [x] Google Play Billing / 支付
- [x] 云端玩家进度
- [x] 多账号与社交能力

## 2. 执行顺序总览

按时间先后，本次上线工作分为 8 个阶段：

1. 收口版本范围与仓库清理
2. 切换正式运行环境
3. 收口广告与隐私合规
4. 收口崩溃、埋点与可观测性
5. 收口数据库与本地数据升级策略
6. 建立发布工程与 release 包验证
7. 完成人工回归与必要自动化补强
8. 准备商店材料并提交测试 / 上线

原则：前一阶段未完成，不进入后一阶段。尤其不要在 release 环境、广告配置、法务材料未收口前开始正式提包。

---

## 3. 第一阶段：收口版本范围与仓库清理

### 3.1 目标

去掉当前版本范围外内容，清掉已确认无用文件，避免后续执行过程中继续出现误导性文档和废弃代码。

### 3.2 执行项

- [ ] 删除未接入导航、仅保留假数据的排行榜页面文件
- [ ] 删除已确认无引用的历史布局与兼容占位类
- [ ] 删除与当前实现状态冲突、已被本执行文档替代的旧文档
- [ ] 保留仍用于 WebView、法务、发布、后台联调的文档和资源文件

### 3.3 验收标准

- [ ] 仓库内不再保留“当前版本不做但仍像要做”的入口性文件
- [ ] 仓库内不再保留“状态过期且会误导执行”的主文档
- [ ] 删除后编译与测试仍通过

---

## 4. 第二阶段：切换正式运行环境

### 4.1 目标

把应用从当前局域网联调态切到正式可上线环境，清理明文流量与测试地址依赖。

### 4.2 执行项

- [ ] 确认正式 API 域名、正式资源域名、正式法务页面域名
- [ ] 将默认环境从本地 `beta` 地址切换为正式线上地址
- [ ] 仅保留 `localhost/127.0.0.1` 给本地 H5 WebServer 使用
- [ ] 评估并关闭 `android:usesCleartextTraffic="true"`
- [ ] 确认全部正式请求改为 HTTPS

### 4.3 验收标准

- [ ] 新安装应用默认进入正式环境
- [ ] release 包不再依赖局域网地址运行
- [ ] 除本地回环地址外，不再允许明文 HTTP 访问

---

## 5. 第三阶段：收口广告与隐私合规

### 5.1 目标

让广告、法务、同意流程、商店披露全部达到正式投放要求。

### 5.2 广告执行项

- [ ] 确认本版本是否上线开屏、插屏、激励、横幅
- [ ] 明确每种广告的位置、触发条件、频控规则、失败降级策略
- [ ] 将测试广告位替换为正式广告位
- [ ] 保持 debug 与 release 的广告配置隔离
- [ ] 在 `BuildConfig.ENABLE_AD_DEBUG=false` 下验证不会误走测试广告逻辑
- [ ] 验证用户拒绝同意时主流程仍可使用

### 5.3 隐私合规执行项

- [ ] 用真实邮箱、主体信息替换隐私政策与用户协议占位内容
- [ ] 确认设置页打开隐私政策、用户协议、广告隐私选项均可用
- [ ] 逐项核对广告 SDK、WebView、本地缓存、玩家标识、日志等数据处理说明
- [ ] 按最终版本填写 Data Safety 草稿
- [ ] 完成 Ads 声明、年龄受众、内容分级确认

### 5.4 验收标准

- [ ] release 包已接入正式广告位
- [ ] UMP 同意流程在首启、设置页重开、拒绝同意场景下行为正确
- [ ] 法务页内容无占位符
- [ ] Play Console 合规信息可直接填写提交

## 6. 第四阶段：收口崩溃、埋点与可观测性

### 6.1 目标

确保线上问题可追踪，关键业务链路可观测。

### 6.2 执行项

- [ ] 确认是否以 Sentry 作为本次正式崩溃平台
- [ ] 在 `gradle.properties` 或 CI 中注入正式 `SENTRY_DSN`
- [ ] 验证崩溃页、非致命异常、本地快照、Sentry 上报全部有效
- [ ] 确认当前核心埋点事件已覆盖：首页、任务达成、领奖、升级、游戏下载、广告事件
- [ ] 如需对接第三方分析平台，在 `AnalyticsManager.track()` 内接入真实 SDK

### 6.3 验收标准

- [ ] 人工制造一次非致命异常，记录可见
- [ ] 人工制造一次崩溃，崩溃页和后台均可见
- [ ] 完整主链路日志可追踪：冷启动 -> 同意协议 -> 首页 -> 游戏 -> 达成 -> 领奖 -> 升级

## 7. 第五阶段：收口数据库与本地数据升级策略

### 7.1 目标

### 7.3 验收标准

- [ ] 正式版本升级后不清库

## 8. 第六阶段：建立发布工程与 release 包验证

### 8.3 验收标准

## 9. 第七阶段：完成人工回归与必要自动化补强

### 9.1 目标

把当前“主要靠人工确认”的状态，提升到“关键风险有明确回归清单，必要点有自动化兜底”。

### 9.2 必跑人工回归

- [ ] 首次安装 -> 协议确认 -> 首页可见推荐挑战
- [ ] 启动一款游戏 -> 产生任务进度 -> 返回首页状态刷新
- [ ] 达成任务 -> 领取奖励 -> EXP / 金币更新
- [ ] 满足升级条件 -> 升级成功 -> 解锁下一章
- [ ] 断网启动 -> 使用缓存或 assets fallback 仍可运行
- [ ] 清缓存 / 无缓存 / 接口超时 / 配置版本变化场景
- [ ] 广告同意、拒绝、失败、关闭场景
- [ ] release 包冷启动、后台切回、弱网场景

### 9.3 建议补强的自动化

- [ ] 为 `LocalAdventureManager` 增加任务领奖、升级、fallback 相关单测
- [ ] 为配置同步和关键状态转换增加最小覆盖
- [ ] 至少保留一份可执行的 release 前回归清单

### 9.4 验收标准

- [ ] 所有关键链路有明确回归结果
- [ ] 没有 P0 阻塞问题遗留到提包前

## 11. 当前建议的先后次序

如果按最短路径推进，本周到上线前的推荐顺序如下：

1. 先清理仓库中的废弃页面、废弃布局、过期文档

5. 再补数据库 migration 和 release signing
6. 再做一轮完整 release 包回归
7. 最后准备商店材料并提交内部测试

# 6. 埋点分析（必须补步骤）

上线后如果没有埋点，将无法判断任务体系是否有效，也无法判断留存驱动是否成立。

## 6.1 埋点目标
- [ ] 判断首页成长体系是否有效
- [ ] 判断玩家是否在任务链路中流失
- [ ] 判断哪些游戏最能带来留存
- [ ] 判断广告对体验是否有伤害

## 6.2 埋点执行步骤

### 阶段 1：定义核心事件
至少定义以下事件：
- [ ] 首次启动
- [ ] 首页曝光
- [ ] 玩家登录成功
- [ ] 任务曝光
- [ ] 任务领取
- [ ] 任务完成
- [ ] 奖励领取
- [ ] 游戏详情曝光
- [ ] 点击开始游戏
- [ ] 游戏启动成功
- [ ] 游戏退出
- [ ] 游戏游玩时长
- [ ] SDK 更新开始 / 成功 / 失败
- [ ] 游戏下载开始 / 成功 / 失败
- [ ] 广告展示 / 点击 / 完成 / 失败

### 阶段 2：定义用户漏斗
- [ ] 启动 → 首页曝光 → 领取任务 → 启动游戏 → 完成任务 → 奖励领取 → 次日回访

### 阶段 3：定义属性
- [ ] 玩家等级
- [ ] 玩家任务阶段
- [ ] 当前版本号
- [ ] 当前 SDK 版本号
- [ ] 游戏 ID
- [ ] 任务 ID
- [ ] 广告状态
- [ ] 网络状态

### 阶段 4：落地
- [ ] 形成埋点表
- [ ] 前后端统一字段命名
- [ ] 明确哪些事件由 Native 上报，哪些事件由 H5 上报
- [ ] 对关键链路做联调验收
