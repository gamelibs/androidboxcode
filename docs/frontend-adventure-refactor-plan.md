# GameBoxOne 前端历练化改造执行方案

> 文档目标：指导 `GameBoxOne` 前端进入“历练挑战升级首页”改造阶段。  
> 适用前提：**单机成长感、弱依赖后端、后台可运营、离线可跑、先做上线版本。**  
> 执行原则：**优先改造首页主链路，不重做整个 App。**

---

# 1. 总原则确认

本次前端改造统一按以下原则执行：

## 1.1 单机成长感
- 玩家首次进入 App 时，由本地初始化一个“本地玩家档案”
- 玩家等级、历练阶段、任务完成数、奖励领取状态由 App 本地维护
- 玩家能在离线状态下继续看到自己的成长、等级和章节进度

## 1.2 弱依赖后端
- 后端不参与逐玩家进度计算
- 后端不记录每个玩家的任务完成状态
- 后端只负责下发全局配置：章节、任务、奖励、推荐、保底、版本
- App 本地根据这些规则做判断与渲染

## 1.3 后台可运营
- 页面结构和数据结构必须支持后续运营替换任务、调整章节、切换推荐内容
- App 端不把任务写死在页面里
- App 端只消费配置并执行本地状态流转

## 1.4 离线可跑
- 没有网络时也能展示首页历练页
- 没有网络时也能看到当前等级、章节、已完成任务、待领奖励
- 没有网络时优先使用本地缓存配置或保底配置

## 1.5 先做上线版本
- 先完成主链路：`首页历练 -> 启动游戏 -> 回流挑战结果 -> 完成任务 -> 领奖 -> 升级`
- 暂不做复杂社交、排行榜、支付、云端同步
- 不做大规模 UI 重构，只在现有简约风格基础上重构首页信息结构

# 2. 本次前端改造的范围

## 2.1 必改页面

### A. `HomeScreen`
改造目标：
- 从“游戏列表首页”改成“历练挑战首页”
- 成为玩家第一主场

### B. `HomeStatusHeader`
改造目标：
- 从简单等级条升级为“玩家身份卡 + 升级进度头部卡”
- 承载等级、称号、经验、当前章节摘要

### C. `AdventureScreen`
改造目标：
- 从原型图页面升级为“历练章节总览页”
- 展示章节地图、当前章节、历史章节、后续章节预告

### D. `MyGameScreen`
改造目标：
- 保留已安装游戏与玩家面板能力
- 增加“与当前历练相关的已安装游戏”联动展示
- 不再承担首页主推进任务

---

## 2.2 需要联动的页面与模块

### A. `GameDetailScreen`
- 增加历练任务上下文展示（该游戏关联了什么挑战）
- 启动游戏前让玩家明确目标

### B. `WebViewActivity`
- 作为挑战结果回流入口
- 负责接收 H5 或本地上报的分数 / 关卡 / 通关事件

### C. `GameDataBridge`
- 承接 H5 -> Native 的任务事件桥接
- 支持最小挑战结果上报协议

### D. `MainScreen` / `NavGraphBuilders`
- 保持现有页面骨架
- 首页仍使用 `HomeScreen`
- `AdventureScreen` 作为“历练全览页”，而不是顶替首页

---

## 2.3 本次不改或降级处理的范围

- `RankingScreen`：隐藏，不纳入本次版本
- 支付：不开发
- 社交互动：不纳入本次版本
- 云端进度同步：不纳入本次版本
- 多账号切换：不纳入本次版本

---

# 3. 前端必须本地化的逻辑

这是本次改造最重要的一部分。

## 3.1 本地玩家初始化
- 首次启动时在本地生成 `localPlayerId`
- 初始化本地等级为 Lv.1 探索者
- 初始化当前章节为第一章
- 初始化默认经验、金币、奖励记录

## 3.2 本地任务进度
- 每个任务本地记录状态：
  - locked
  - available
  - in_progress
  - achieved
  - claimed
  - completed
- 本地保存当前最好成绩
- 本地保存当前最高关卡
- 本地保存通关次数

## 3.3 本地奖励发放
- 任务达成后先本地变为 `achieved`
- 玩家点击领奖后本地发放经验/金币/道具
- 奖励必须幂等，避免重复领取

## 3.4 本地升级判断
- 读取当前章节任务状态
- 本地判断是否达到 `7/10` 升级条件
- 满足后进入 `upgrade_ready`
- 玩家点击“立即升阶”后更新本地等级与章节状态

## 3.5 本地保底恢复
- 没有网络时优先读本地缓存配置
- 本地缓存配置不存在时读 assets 保底配置
- 若任务配置不完整，至少保证 Lv.1 第一章能显示并可运行

# 4. 后端最小依赖范围

前端上线版本只依赖最小配置接口，不依赖玩家进度接口。

## 4.1 最小接口集合
- `GET /api/v1/site/adventure/version`
- `GET /api/v1/site/adventure/config`
- `GET /api/v1/site/adventure/home`（可选，作为首页聚合配置）
- `GET /api/v1/site/adventure/chapter/{chapterId}`
- `GET /api/v1/site/adventure/reward-packages`
- `GET /api/v1/site/adventure/fallback`

### 4.1.1 当前对接状态（2026-03-21）

- Android 仍未把 6 个历练接口接入正式调用链
- `AdventureConfigModels.kt` 目前只提供部分 DTO，缺少完整请求封装与缓存读写
- 首页与章节数据仍主要来自 `assets/adventure_config.json` + Room 本地进度
- 局域网联调已统一到 `http://192.168.1.54:13200`，后续主要关注回归测试与断网回退验证

## 4.2 仍可继续沿用的现有接口
- 游戏列表基础接口
- SDK 配置与下载接口

## 4.3 前端不能依赖的能力
- 不能依赖后端返回当前玩家等级
- 不能依赖后端返回玩家任务完成数
- 不能依赖后端给玩家发奖
- 不能依赖后端做升级判断

# 5. 首页重构后的信息结构

首页从上到下建议固定为 7 个模块：

## 模块 1：玩家身份卡
显示：
- 等级
- 称号
- 经验进度
- 当前章节
- 金币/奖励

## 模块 2：本章主任务卡
显示：
- 当前章节名
- 已完成任务数
- 升级还差多少
- 当前章节奖励预览
- 升级条件说明

## 模块 3：今日推荐挑战
显示：
- 最推荐的 3 个任务
- 每个任务带一键开始
- 若有待领奖励，则优先显示奖励卡

## 模块 4：历练进度条
显示：
- 本章 10 个任务点位
- 任务完成进度
- 升级节点高亮

## 模块 5：挑战游戏支撑列表
显示：
- 当前章节 10 个任务对应游戏
- 状态：未开始 / 进行中 / 已达成 / 已完成
- 目标：分数 / 关卡 / 通关

## 模块 6：最近完成动态
显示：
- 最近完成任务
- 最近领取奖励
- 最近解锁章节/等级

## 模块 7：下一等级预告
显示：
- 下一等级称号
- 下一章节主题
- 将解锁的 10 个新挑战方向

---

# 6. 游戏列表的新定位

## 6.1 首页中的游戏列表
不再是全量推荐列表，而是：

**当前章节任务游戏列表**

即：
- 首页只展示当前章节相关的 10 个游戏任务
- 列表服务于任务推进，不服务于泛浏览

## 6.2 全量游戏库
- 仍然保留游戏库能力
- 放入次级入口
- 不抢首页“历练推进”主定位

## 6.3 排序规则
首页任务游戏列表排序建议：
1. 已达成待领奖
2. 最接近完成
3. 正在进行中
4. 未开始
5. 已完成

---

# 7. 前端状态流转设计

## 7.1 任务状态
`locked -> available -> in_progress -> achieved -> claimed -> completed`

## 7.2 章节状态
`locked -> current -> upgrade_ready -> completed`

## 7.3 等级状态
`lv_n -> level_up_pending -> lv_(n+1)`

## 7.4 首页优先展示规则
首页优先展示：
1. 待领奖励
2. 可升级提示
3. 最接近完成的任务
4. 当前章节推荐挑战

---

# 8. 前端改造的分阶段执行步骤

## Phase 1：先把首页历练主链路跑通（上线版本）

### 目标
实现最小闭环：
`首页历练 -> 开始游戏 -> 回流结果 -> 达成任务 -> 领奖 -> 升级`

### P0 对接结果（截至 2026-03-21）

- 已接入 `/api/v1/site/adventure/version`
- 已接入 `/api/v1/site/adventure/config`
- 已接入 `/api/v1/site/adventure/home`
- 已接入 `/api/v1/site/adventure/chapter/{chapterId}`
- 已建立 `远端 config -> Room(app_config) -> assets fallback` 配置读取链路
- 已将默认测试环境切换为 `beta`，默认测试地址为 `http://192.168.1.54:13200`
- 已完成编译验证：`./gradlew :app:assembleDebug` 通过


---

## Phase 2：接入后端配置中心，增强可运营性

### 目标
从“本地写死/半写死”过渡到“后端配置下发 + 本地执行”。

### 要做的事
- [ ] 奖励包与保底配置接入 `/reward-packages`、`/fallback`
- [ ] 将已缓存的 `/reward-packages` 接入任务奖励展示与发放策略
- [ ] 明确并验证 `assets/adventure_config.json` 与远端 `/fallback` 的优先级和一致性校验
- [ ] 补齐 beta 环境冷启动、断网回退、配置版本升级回归用例

### Phase 2 局域网联调说明（当前结果）

1. App 默认环境已改为 `beta`
2. 默认 beta 地址已改为：`http://192.168.1.54:13200`
3. 平台已对齐为 `1003`
4. 在线链路已改为只使用新接口；旧远端回退接口已停用
5. 后续主要验证点已转为：奖励包消费链路、fallback 回退策略、断网与版本升级回归

### Phase 2 推荐实施顺序

1. 先做 `/version` + `/config`
2. 再做 `/home` + `/chapter/{chapterId}`
3. 最后补 `/reward-packages` + `/fallback`

### Phase 2 验收标准
- [ ] 奖励包数据已进入真实奖励展示与发放链路
- [ ] 断网时可稳定回退到本地缓存或 `assets/adventure_config.json`
- [ ] 配置版本升级后可自动刷新并保持本地进度不丢失
- [ ] App 无需发版即可调整任务配置

# 9. 建议的文件级改造顺序

为了减少风险，建议按以下顺序落代码：

## 第一批：数据与状态基础层
- `UserLevelConfig`
- 本地历练数据模型
- 本地任务进度存储层
- 本地升级判断层

## 第二批：首页结构层
- `HomeStatusHeader`
- `HomeScreen`
- 首页任务卡 / 历练进度组件 / 奖励卡组件

## 第三批：挑战结果回流层
- `WebViewActivity`
- `GameDataBridge`
- 游戏结果转换为任务进度逻辑

## 第四批：次级页面联动
- `AdventureScreen`
- `MyGameScreen`
- `GameDetailScreen`

## 第五批：配置层接入
- 远端配置读取
- 本地缓存与保底配置切换

# 10. UI 风格执行要求

本次前端改造不另起一套复杂视觉体系，直接沿用当前风格做增强。

## 10.1 风格关键词
- 简约
- 清爽
- 小清新
- 轻冒险
- 卡片化
- 圆角化

## 10.2 视觉约束
- 不做重度玄幻特效
- 不做复杂地图型大场景首页
- 不做大面积深色压迫风
- 以白底 / 浅色底为主
- 用浅绿色、薄荷色、暖白色做主色调

## 10.3 交互原则
- 一屏内要让玩家看懂“我是谁、我在哪、我要做什么”
- 每次任务完成要有轻反馈
- 每次升级要有强反馈
- 每个按钮都要有明确目的，不做纯装饰区块

---

# 11. 与后台并行开发时的协作边界

你在另一台机器上做后台时，前端可先按以下方式并行推进：

## 前端先做
- 本地数据模型
- 首页 UI 结构
- 本地任务状态机
- 本地奖励逻辑
- 本地升级逻辑
- 本地保底配置

## 后端后接
- 配置 JSON 结构
- 配置版本接口
- 历练章节接口
- 奖励包接口
- 保底配置接口

## 联调时只需要对齐
- 字段名
- 章节ID
- 任务ID
- 游戏ID
- 奖励包ID
- 配置版本号

---

# 12. 最终结论

从现在开始，`GameBoxOne` 前端改造统一按以下思路落地：

**首页变历练、进度在本地、规则可配置、离线能运行、先保主链路上线。**

这意味着：
- 不再以“游戏列表首页”为主
- 改为“历练挑战升级首页”为主
- 不依赖用户系统做成长记录
- 不依赖后端做玩家状态判断
- 前后端可以并行开发并快速进入实现阶段
