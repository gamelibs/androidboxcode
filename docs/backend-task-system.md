# GameBoxOne 后台任务运营对齐文档（P1）

> **文档目标**：用于和后台、客户端、测试统一当前阶段任务口径。  
> **当前阶段**：后台接口能力已基本完成，当前进入 **App 完整消费 + 联调调试 + 验收收口** 阶段。  
> **设计原则**：后端只做全局配置中心与运营发布能力；玩家进度、奖励领取、等级推进均由 App 本地维护。

---

# 1. 当前阶段结论

## 1.1 当前不是“继续建设后台”，而是“消费已有后台能力”

基于当前已拿到的后端文档、现有接口清单与既有联调结论，现阶段更准确的判断是：

- **运营后台相关接口已经基本完成**
- **任务配置、章节配置、发布、回滚、历史等能力已具备基础闭环**
- 当前 P1 的主要工作已从“后台建设”转向“App 消费完成 + 联调验收完成”

## 1.2 需要替换掉的旧认知

以下旧表述不再适用：

- “现在只有游戏列表接口，没有后台”
- “还没有任务系统接口”
- “运营后台还没开始做”

当前应统一为：

> **后台配置中心和运营接口已经基本齐全，当前版本剩余工作主要在 App 侧完整消费、回归调试和发布验收。**

## 1.3 当前版本的边界

当前版本只做：
- 历练配置消费
- 章节任务消费
- 奖励包消费
- fallback 回退验收
- 发布 / 回滚 / 历史联调
- 游戏绑定校验

当前版本不做：
- 玩家云端进度
- 云端领奖
- 云端升级判断
- 云同步
- 多账号
- 社交功能
- 支付与 Billing

# 3. 当前 App 与后台职责边界

## 3.1 后端职责

后端负责：
- 下发统一等级配置
- 下发章节与任务配置
- 下发奖励包配置
- 下发首页推荐配置
- 提供发布、回滚、历史能力
- 提供 fallback 数据

## 3.2 App 职责

App 负责：
- 本地创建匿名玩家档案
- 本地保存等级、EXP、金币、奖励领取记录
- 本地保存章节进度与任务进度
- 基于本地事件计算 `未开始 / 进行中 / 已达成待领取 / 已完成`
- 本地判断是否满足升级条件
- 将 `home` 接口提供的推荐任务 ID 与本地任务状态合并渲染

## 3.3 当前明确不做的事情

以下能力不要再写进当前阶段需求：

- 后端存储逐玩家任务状态
- 后端发放逐玩家奖励
- 后端计算逐玩家升级结果
- 云端领奖记录
- 跨设备进度同步

# 4. P1 要做的完整说明

## 4.1 P1 的核心目标

**把现有后台接口完整消费完、把联调问题清干净、把回归场景跑完整，然后进入 P2 最终测试。**

## 4.2 P1 客户端侧任务

### A. 首页完整消费

客户端需要完成：
- 消费 `GET /api/v1/site/adventure/home`
- 按 `currentChapter` 展示当前章节主卡
- 按 `recommendedTaskIds` 生成首页推荐任务卡
- 按 `nextLevelPreview` 展示下一级预告
- 结合本地进度计算推荐任务状态

### B. 章节任务完整消费

客户端需要完成：
- 消费 `GET /api/v1/site/adventure/chapter/{id}`
- 展示本章 10 个任务列表
- 正确关联 `task.gameId` 与游戏列表数据
- 支持开始挑战 / 继续挑战 / 已达成待领取 / 已完成 等状态展示

### C. 奖励包完整消费

客户端需要完成：
- 消费 `GET /api/v1/site/adventure/reward-packages`
- 将奖励包接入真实奖励弹窗、奖励展示、本地记录
- 让任务奖励 / 章节奖励 / 升级奖励都能按本地规则兑现

说明：
- 这里是**本地奖励兑现**，不是云端领奖
- 当前不新增任何服务端逐玩家领奖接口

### D. fallback 完整验收

客户端需要完成：
- 验证 `GET /api/v1/site/adventure/fallback`
- 验证 `assets/adventure_config.json` 本地保底能力
- 验证冷启动无网、接口超时、配置更新失败、无缓存等场景
- 确保异常时首页和历练链路仍可最小可运行

### E. 版本与缓存回归

客户端需要完成：
- `version -> config` 的更新链路验证
- 新版本发布后的缓存刷新验证
- 回滚后的旧版本恢复验证
- 本地缓存命中与无缓存场景回归

## 4.3 P1 联调侧任务

### A. 发布联调

需要确认：
- publish 后 `version/config/home/chapter` 数据同步更新
- App 能识别新 `configVersion`
- UI 侧能正确刷新新配置

### B. 回滚联调

需要确认：
- rollback 后 `version` 变化符合预期
- App 能正确回退到可用配置
- 首页、章节页、奖励展示不出现脏数据

### C. 历史记录联调

需要确认：
- `history` 可追踪版本发布时间
- `history` 可追踪回滚记录
- 测试能据此定位问题批次

### D. 批量绑定 / 槽位联调

需要确认：
- `batch-bind` 执行后任务与真实游戏绑定正确
- `chapter/{id}/task/{slot}` 调整后 App 展示同步正确
- 不出现 `task.gameId` 与游戏列表断链情况

# 8. 与首页历练方案的对应关系

当前 P1 的消费目标，需直接服务首页历练主路径：

1. 首页展示当前等级与当前章节
2. 首页展示推荐 3 个任务
3. 玩家进入游戏后由本地事件系统推进任务
4. 达成后本地展示奖励并刷新任务状态
5. 满足条件后本地触发升级提示

也就是说：

- 后台负责把“这一章做什么”配置出来
- App 负责把“这个玩家现在做到哪了”算出来
